# CRM 主流程跑通开发计划

**目标：** 先把 CRM 从系统基础、产品管理、产品需求到销售主链路的整体流程跑通，再逐步回头细化每个页面和功能细节。

**推进原则：**

- 先跑通依赖链路，不在单个模块过早打磨细节。
- 后端业务逻辑和既有接口优先保持稳定，前端页面先调整到可用、可联调、可验证。
- 每完成一个阶段，把前面的 `[ ]` 改成 `[·]`。
- 当前阶段只追求“功能可用、流程能走、依赖清楚”，后续再做页面细节、权限矩阵、异常状态和测试补强。

---

## 一、系统基础模块

- [·] **组织架构**
  - 当前状态：已基本可用。
  - 作用：为人员、部门、负责人、数据范围、审批人选择提供基础数据。
  - 后续只做必要修补，不再作为当前主线阻塞项。

- [·] **角色权限**
  - 当前状态：角色权限页面已能使用，权限配置和成员授权入口可用。
  - 作用：为产品、产品需求、销售模块提供菜单、按钮、接口、数据范围控制基础。
  - 后续细化项：权限矩阵、角色模型、按钮级验证、无权限接口验证，放到主流程跑通后补。

- [ ] **流程设置 / 审批流程**
  - 当前目标：先把审批流程配置页面跑通，能配置并保存一条可用于业务模块的审批流程。
  - 优先验证：
    - 审批流程列表是否可用。
    - 新增/编辑审批流程是否可用。
    - 审批节点、审批人、条件配置是否可保存。
    - 待办、已办、抄送入口是否可进入。
  - 先接入目标：产品需求审批。
  - 暂不深入：复杂条件、跨模块审批、多级异常场景。

- [ ] **消息设置**
  - 当前目标：确认消息公告、通知配置、审批通知入口可用。
  - 优先验证：
    - 消息设置页面是否可打开。
    - 公告/通知新增、编辑、启停是否可用。
    - 审批动作是否能留下消息通知入口。
  - 作用：后面产品需求审批、报价审批、合同审批需要消息提示。

- [ ] **企业设置**
  - 当前目标：确认系统基础配置能支持后续模块。
  - 优先验证：
    - 企业信息、登录配置、邮件配置是否可打开和保存。
    - 业务编号、通知、导出等相关配置是否已有入口。
  - 作用：审批通知、系统展示、业务编号等后续功能会依赖这里。

- [ ] **系统日志**
  - 当前目标：确认关键操作有日志入口。
  - 优先验证：
    - 操作日志页面是否可打开。
    - 登录日志页面是否可打开。
    - 角色、组织、审批、产品相关操作是否能查到记录。
  - 作用：后续业务模块联调时用于排查流程和权限问题。

**系统模块阶段完成标准：**

- 组织架构、角色权限、流程设置、消息设置、企业设置、系统日志都能进入并完成基础操作。
- 产品需求可以使用组织、角色、审批作为依赖继续开发。

## 二、产品管理模块

- [ ] **产品集 / 产品基础信息**
  - 当前目标：先让产品列表、新增、编辑、详情可用。
  - 优先验证：
    - 产品列表展示、搜索、筛选。
    - 产品新增、编辑、删除。
    - 产品详情信息展示。
  - 作用：销售线索、商机、报价后续需要关联产品。

- [ ] **产品版本 / 产品模块**
  - 当前目标：确认产品下的版本、模块结构能维护。
  - 优先验证：
    - 产品版本新增、编辑、删除。
    - 产品模块新增、编辑、删除。
    - 产品详情中能看到版本和模块关系。
  - 作用：产品需求需要关联到具体产品、版本或模块。

- [ ] **产品价格**
  - 当前目标：让报价可用的产品价格数据先稳定。
  - 优先验证：
    - 价格列表、新增、编辑、删除。
    - 价格复制、导入、导出如已有入口则确认可用。
    - 产品改价后，后续报价是否需要保存快照先记录清楚。
  - 作用：报价管理、商机产品明细会依赖价格。

**产品管理阶段完成标准：**

- 产品、版本、模块、价格能形成可维护的产品基础数据。
- 产品数据可以被产品需求和销售模块引用。

---

## 三、产品需求管理模块

- [ ] **产品需求列表和详情**
  - 当前目标：产品需求能创建、查看、筛选。
  - 依赖：组织架构、角色权限、产品管理。
  - 优先验证：
    - 需求列表、筛选、搜索。
    - 需求新增、编辑、详情。
    - 需求关联产品、版本、模块、负责人。

- [ ] **产品需求状态流转**
  - 当前目标：先跑通从提报到完成的一条主流程。
  - 建议状态：
    - 需求池
    - 需求评估
    - 产品设计
    - 技术评审
    - 开发中
    - 测试中
    - 产品验收
    - 待发布
    - 已上线
  - 暂不深入：复杂回退、并行评审、跨部门例外规则。

- [ ] **产品需求审批**
  - 当前目标：把产品需求作为第一个审批落地资源。
  - 依赖：流程设置。
  - 优先验证：
    - 发起审批。
    - 审批通过。
    - 审批驳回。
    - 撤回审批。
    - 待办/已办/抄送可见。

- [ ] **产品需求消息和日志**
  - 当前目标：产品需求关键动作有基本留痕。
  - 优先验证：
    - 新增、编辑、状态变更、审批动作是否有日志。
    - 审批待办或结果是否有消息入口。

**产品需求阶段完成标准：**

- 产品需求可以从创建、关联产品、审批、状态流转到完成形成闭环。
- 产品需求闭环完成后，再进入销售模块开发优化。

---

## 四、销售 CRM 主链路

- [ ] **客户管理**
  - 当前目标：稳定客户主数据。
  - 优先验证：
    - 客户列表、新增、编辑、详情。
    - 联系人、公海、协作人、负责人。
    - 数据范围是否影响客户列表。

- [ ] **线索管理**
  - 当前目标：跑通线索收集和转化。
  - 优先验证：
    - 线索列表、新增、编辑、详情。
    - 线索池、领取、分配。
    - 线索转客户、转商机。
    - 线索关联产品需求或产品意向，如已有字段则保留。

- [ ] **商机管理**
  - 当前目标：跑通销售过程。
  - 优先验证：
    - 商机列表、新增、编辑、详情。
    - 商机阶段推进。
    - 商机关联客户、联系人、产品。
    - 赢单、输单、关闭规则。

- [ ] **报价管理**
  - 当前目标：跑通基于产品的报价流程。
  - 依赖：产品管理、商机管理、审批流程。
  - 优先验证：
    - 从商机创建报价。
    - 报价选择产品和价格。
    - 报价金额计算。
    - 报价审批、下载、作废。
    - 产品价格是否需要保存报价快照。

- [ ] **合同管理**
  - 当前目标：跑通成交和回款基础流程。
  - 依赖：客户、商机、报价、审批流程。
  - 优先验证：
    - 合同新增、编辑、详情。
    - 合同关联客户、商机、报价、产品明细。
    - 合同审批。
    - 回款计划、回款记录。
    - 发票记录。

**销售阶段完成标准：**

- 销售主链路可以从线索、客户、商机、报价到合同跑通。
- 产品能被线索、商机、报价引用。
- 审批、权限、消息、日志能支撑主要销售动作。

## 五、最后统一优化

- [ ] **页面细节统一**
  - 对齐截图和设计稿。
  - 统一系统模块、产品模块、销售模块的布局、表格、筛选、详情页风格。

- [ ] **权限矩阵补全**
  - 补菜单权限、按钮权限、接口权限、数据范围验证。
  - 按系统、产品、产品需求、客户、线索、商机、报价、合同补矩阵。

- [ ] **异常流程补全**
  - 无权限。
  - 空数据。
  - 重复数据。
  - 审批驳回。
  - 数据范围不一致。
  - 导入导出失败。

- [ ] **联调和验收记录**
  - 每个模块补字段清单、接口清单、状态流转说明、问题清单。
  - 最后统一补测试记录和部署验收。
