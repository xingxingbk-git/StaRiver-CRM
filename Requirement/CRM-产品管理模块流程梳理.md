# CRM\-产品管理模块流程梳理

# 产品集（整体与竞品不同）

**产品集主流程**

进入产品集首页，上方以卡片形式展示产品，例如 `StaRiver AI 中台`、`OptiQA 智能质检`。

首页下方展示版本 / 活动记录表格，每行提供 `查看路线图` 操作，点击进入对应产品详情的路线图视图。

**新建产品流程**

用户在产品集首页点击 `+ 新建产品`，进入新建产品页面。

新建产品页面主要填写以下内容：

- 产品基础信息（代号、全称、版本号）

- 产品状态

- 计划发布日期

- 产品描述

- 负责人信息（产品负责人、研发负责人）

- 模块架构（主模块下可添加二级子模块）

产品状态下拉选择项包括：

- 规划中

- 开发中

- 已发布

保存后，用户进入新建产品的产品详情页。

**产品详情流程**

用户点击产品卡片，或在列表中点击 `查看路线图`，进入产品详情。

产品详情顶部展示产品名称、代号、版本信息。详情主体通过 tab 切换不同视图：

- 总览

    总览页用于展示产品概览和使用客户等信息。

- 模块架构

    模块架构页用于展示产品的整体结构，模块层级和负责人等信息，产品需求待发布时需关联发布版本与所属模块，所以这里的每个模块会对应显示所关联的待发布需求数。

- 需求池

    需求池页展示该产品关联的所有 PRM 需求列表。

    用户可以从这里进入具体 PRM 需求详情，继续查看需求描述、验收标准、流程记录等信息。

- 路线图

    路线图页按版本展示产品规划路线。

    点击新增版本，填写相关信息及说明后创建新版本。

    点击条目可进入对应版本详情：

    - 查看版本说明

    - 查看版本的关联需求

    - 推进版本阶段（规划 \-\> 开发 \-\> 发布）

    - 删除版本（已发布的版本不可删除）

    - 产品文档

- 产品文档

    产品文档页展示产品相关文档列表。

    用户可以：

    - 预览文档及查看文档信息

    - 上传新文档

    - 删除已有文档

```Markdown
左侧导航
  ↓
产品需求 / 产品集
  ↓
产品集首页
  ├─ 点击新建产品
  │    ↓
  │  新建产品表单
  │    ├─ 选择产品状态
  │    └─ 保存后进入详情
  │
  └─ 点击产品卡片 / 查看路线图
       ↓
     产品详情
       ├─ 总览
       ├─ 模块架构
       ├─ 需求池
       ├─ 路线图
       │    ├─ 新增版本弹窗
       │    └─ 版本详情弹窗
       └─ 产品文档
            └─ 上传文档弹窗
            └─ 文档详情弹窗
```

# 产品需求管理（竞品没有）

**产品需求主流程**

进入产品需求管理页面，默认展示 PRM需求池。页面上方展示需求统计，下方展示产品需求列表。

用户可以：

- 按产品筛选需求，例如 StaRiver、OptiQA

- 按状态筛选需求

- 点击 提报需求 新建产品需求

- 点击 需求条目 进入 PRM 需求详情

**提报需求流程**

用户在 PRM 需求池点击 【提报需求】 ，进入新建产品需求页面。

新建产品需求页面主要填写以下内容：

- 需求标题

- 需求类型（功能优化、体验优化、性能改进）

- 需求来源（客户、售前、内部、竞品）

- 目标产品

- 期望上线时间

- 优先级

- 需求描述（富文本，可上传附件或者粘贴飞书链接，文本描述建议按照 As\-a / I\-want / So\-that 结构填写）

- 验收标准（富文本，建议按照 Given 前置条件 / When 操作动作 / Then 预期结果 结构填写）

填写完成后点击提交，需求进入 PRM 需求池，并推送产品经理进行评审。

**PRM 需求详情流程**

用户点击需求列表中的需求条目，进入对应的 PRM 需求详情。

详情页顶部展示需求标题、需求编号、优先级、产品代号、需求类型、负责人、需求来源、期望上线时间等信息。

详情页主体版块：

- 流程进度（展示当前需求所处阶段，以及已完成、当前、待处理的阶段状态）

- 需求描述

- 验收标准

- 流程记录

**阶段流转流程**

PRM 需求从提交后进入完整闭环流程：

`提交 → 需求池 → 需求评审 → 产品设计 → 技术评审 → 开发 → 测试 → 产品验收 → 发布 → 完成`

流程进度中，已完成阶段会绿色高亮展示，当前阶段会蓝色高亮展示。

1. 需求评审

需求创建后自动进入评审阶段，产品经理在审批中心查看产品需求描述等信息进行评审。

评审通过后，需求进入产品设计阶段。

如果评审未通过，需求回到需求池，可再次编辑后重新提交评审或者删除需求。

2. 产品设计

产品设计阶段用于设计产品方案。

点击提交后显示 提交产品设计 弹窗，填写产品设计说明，可插入富文本内容、链接、附件等内容。

提交后，需求自动进入技术评审阶段，自动在流程记录中生成提交信息记录。

3. 技术评审

技术评审阶段用于确认技术实现方案。

研发负责人点击提交后打开 提交产品详设 弹窗，填写详细设计方案，可插入富文本内容、链接、附件等。

提交后，需求进入开发阶段。

如果设计方案有问题，填写问题原因，退回至产品设计。

4. 开发

开发阶段用于研发实现需求。

开发人员完成开发后，点击提交打开 提交开发说明 弹窗，填写开发说明、实现范围、影响说明或相关附件。

提交后，需求进入测试阶段。

5. 测试

测试阶段用于验证需求是否满足验收标准。

测试人员完成测试后，点击提交打开 提交测试结果 弹窗，填写测试结果、测试结论、问题说明或相关附件。

提交后，需求进入产品验收阶段。

如果测试出Bug，填写测试问题，退回至开发。

6. 产品验收

产品验收阶段由产品侧确认需求是否可进入发布。

验收通过后，点击提交打开 提交验收说明 弹窗。

该弹窗除填写验收说明外，还需要关联：

- 发布版本

- 所属模块

确认后，需求进入待发布状态。

如果验收有问题，填写问题说明，退回至开发。

7. 待发布

关联发布版本后，需求进入待发布状态，等待产品新版本发布，需求状态变为完成状态。

用户可在点击 前往产品发布 跳转到产品详情页\-产品路线图页面，对应产品版本完成发布。

**与产品集的联动**

产品需求与产品集存在强关联。

新建需求时需要选择目标产品。需求进入产品验收并通过后，需要选择发布版本和所属模块。

因此，产品需求最终会沉淀到产品集的以下位置：

- 产品详情 / 需求池

- 产品详情 / 路线图 / 版本详情

- 产品模块架构中对应的待发布需求数

当需求进入待发布状态后，用户点击 前往产品发布，应跳转到产品版本路线图。

```Markdown
PRM需求池
  ├─ 筛选产品 / 状态
  ├─ 点击 提报需求
  │    ↓
  │  新建产品需求
  │    ├─ 填写基础信息
  │    ├─ 选择需求类型
  │    ├─ 选择需求来源
  │    ├─ 填写需求描述
  │    ├─ 填写验收标准
  │    └─ 提交后进入需求池并推送产品经理进行评审
  │
  └─ 点击需求池条目
       ↓
     PRM需求详情
       ↓
     需求评审
       ├─ 评审通过后（产品经理在审批中心审批）
            ↓
     产品设计
       └─ 提交产品设计
            ↓
     技术评审
       └─ 提交产品详设
            ↓
     开发
       └─ 提交开发说明
            ↓
     测试
       └─ 提交测试结果
            ↓
     产品验收
       └─ 提交验收说明
            ├─ 选择发布版本
            └─ 选择所属模块
            ↓
     待发布
       ↓
     前往产品发布
       ↓
     发布 / 完成
```
